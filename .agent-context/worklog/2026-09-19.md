## Plugin slimmed to one hook and two skills

Purpose: continue the 2026-09-18 rework — drop every mechanism the Chinese rule and skills already express in text. [Prior context](2026-09-18.md#rule-reorganized-around-the-workflow).

- **`sync-context` deleted.** It was self-contradictory: the description advertised "task state" while its own instructions routed task state to `update-progress`. Split by content type instead — knowledge files (`ARCHITECTURE`/`COMMANDS`/`CONFIG`/`CONVENTIONS`/`MEMORY`) now belong to `bootstrap-context`, which owns both creation and incremental update; state files (`PROGRESS` + `worklog`) stay with `update-progress`. Removed from `.codebuddy-plugin/plugin.json`, the Codex `longDescription`, both READMEs and the repo. Cursor and Codex declare `skills` as a directory, so deleting the folder sufficed.
- **Rule's Project Memory line cut 130 → 64 chars.** It now only points at the two skills and keeps the single-owner principle (`一条事实只存一处`). Write order, migration dates and next-check conditions already live in `update-progress`.
- **Stop hook removed entirely.** The 600-line large-file check was `work-signal.py`'s only function (per its own docstring), so removing the check meant removing the hook: `work-signal.py`, `stop-work-review.sh`, `handoff-signal.py` (it `runpy`-executed `work-signal.py` and would have crashed on next Stop), `stop-handoff-reminder.sh`, and `session-start.sh` (orphaned since plan A). `hooks.json` and `codebuddy-hooks.json` are now `{"hooks": {}}`; `codex-hooks.json` keeps only SessionStart.

Conclusion: injection is now one hook — Codex SessionStart delivering the protocol — with Cursor/CodeBuddy loading `rules/` directly. Tests 43 → 30 after the `StopSignal` class went away. Validator clean.

## Removal exposed two hidden dependencies

Both surfaced by re-scanning *after* the delete, not by the delete itself:

1. `install-local.sh` ran `chmod +x "$dest"/hooks/scripts/*.sh`. With every `.sh` gone the glob stayed literal and **the installer failed outright**. Replaced with a guarded loop that skips when nothing matches.
2. The packaging test asserted byte-identity for `hooks/scripts/handoff-signal.py` and the exec bit on `session-start.sh` — both just deleted. Repointed at `session-context.py`; dropped the exec-bit assertion since hooks now invoke Python via `python3` and need no exec bit.

Lesson: a delete is not finished when the file is gone — grep its name across `scripts/`, `plugins/` and `.agent-context/` before and after.

## Installed copies lag the source

CodeBuddy logged `work-signal.py: No such file or directory` right after the deletion: source configs were already empty, but `~/.codebuddy/plugins/...` and `~/.cursor/plugins/local/...` still carried the old Stop config. Fixed by `./scripts/install-local.sh all` plus a host reload. Expected whenever a hook is removed, and harmless — Stop was advisory, so the failure was log noise only. Worth remembering alongside the earlier finding that CodeBuddy loads the plugin live from the repo source: source and installed copy can disagree until reinstalled.
