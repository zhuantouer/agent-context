## CodeBuddy rules loaded from the source tree

Symptom: after the rename, the CodeBuddy rules panel resolved `agentic-protocol-core.mdc` to `/Users/zishuaizhang/workspace/agentic-protocol/plugins/agentic-protocol/rules/` instead of the installed copy under `~/.codebuddy/plugins/`.

Root cause: `install-local.sh` ran `codebuddy plugin marketplace add ${REPO_ROOT}`, registering the repository as a **directory marketplace**. Such marketplaces are referenced in place (`known_marketplaces.json` sets `installLocation` to the source path, no clone under `~/.codebuddy/plugins/marketplaces/`), so the enabled plugin resolved its rule from the source tree and the `copy_plugin` output was shadowed. The 2026-09-18 finding "the IDE loads the plugin live from the repo source dir" described this same mechanism; the user now judges it a defect, so the marketplace install path was redirected (`--plugin-dir` still loads source by design). Second residue: `agent-context-marketplace` still pointed at the deleted `~/workspace/agent-context`, and `settings.json` kept `agent-context@agent-context-marketplace: true` — the installer's legacy cleanup covered plugin names but never marketplace registrations or enabled keys.

Fix: the CodeBuddy leg now mirrors Codex — the host loads the installed copy. The script writes a local marketplace manifest at `~/.codebuddy/plugin-marketplaces/agentic-protocol-marketplace/.codebuddy-plugin/marketplace.json` whose plugin source is `../../plugins/agentic-protocol` (relative resolution against the marketplace's own directory was confirmed by a failing install printing the resolved path), then re-adds the marketplace and reinstalls, and removes legacy marketplace registrations by name first. The live host was repaired with the same steps; the stale enabled key was removed by editing `settings.json` directly (`plugin uninstall` cannot run because its marketplace no longer exists).

Validation: `bash -n` clean; a full `./scripts/install-local.sh codebuddy` run left exactly one local marketplace registered and only `agentic-protocol@agentic-protocol-marketplace` enabled; 30 tests OK, validator clean. This reinstall also delivered 2.0.1 to the CodeBuddy host, which the version entry above had left outstanding. Still unverified in the IDE: after `/reload-plugins` the rules panel should show a `~/.codebuddy` path, and a fresh chat must still receive `# Agentic 方法论`.

## Second source of the same symptom: project-scope dogfooding

Finding: the fix above only covered the **user-scope** path. The repository root also shipped `.codebuddy/settings.json` (added 2026-09-03, "so this repo dogfoods the plugin") declaring `extraKnownMarketplaces.agentic-protocol-marketplace = {"source": {"source": "directory", "path": "."}}` plus `enabledPlugins: agentic-protocol@agentic-protocol-marketplace`. Resolution chain: project directory as marketplace → root `.codebuddy-plugin/marketplace.json` → `./plugins/agentic-protocol` → `plugins/agentic-protocol/rules/*.mdc`, presented as a **project rule**. That is why this repo showed the source-tree path while other projects show `~/.codebuddy`: they have no project-scope settings, so only the user-scope install applies. Consequence before removal: the protocol could load twice — once from the user install and once from the source tree.

Decision: the user chose to delete the file (option: drop dogfooding entirely), so the repo now behaves like any other project. Reversible via git; nothing in `install-local.sh`, the validator or the test suite referenced it, and the user-scope marketplace registration in `~/.codebuddy/plugins/known_marketplaces.json` is what activates the plugin here now. `git rm .codebuddy/settings.json`; 30 tests OK, validator clean.

Declined (superseded below): renaming `plugins/` or flattening `plugins/agentic-protocol/` to one level.
