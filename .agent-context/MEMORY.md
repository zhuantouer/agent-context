# Project Memory

## Decisions

| 2026-09-03 | CodeBuddy is a hybrid host: deliver the protocol through plugin `rules/` (the Cursor mechanism) and speak Claude-style hook JSON (the Codex mechanism). SessionStart injects the handoff capsule only — never the protocol. | The 2026-08-03 lesson is that packaging parity is not product parity. CodeBuddy IDE 4.5.0+ ships Rule as a plugin component and 4.7.2 recursively discovers plugin `rules/`; Codex's SessionStart injection exists because Codex has no rules slot. Using it on CodeBuddy would double-load the protocol on IDE. `plugin.json` has no `rules` field, so discovery is directory convention, not a manifest path. Stop stays advisory via `systemMessage`, never `decision: block`. |
| 2026-09-03 | CodeBuddy `plugin.json` `skills` must be an array of paths (`["./skills/"]`), even though the published schema says `string | array`. | `codebuddy plugin validate` rejected `"./skills/"` with `Field "skills" must be an array` (the only error; `hooks` as a string passed). Docs and CLI disagree; the CLI is what installs. Keep hooks as a string path to `codebuddy-hooks.json` so the default `hooks/hooks.json` (Cursor camelCase) is not loaded. |
| 2026-09-02 | Terminology fidelity is a language rule, not a preservation-list item: `Response Style` now reads "Reply in the user's language, but write each term the way its field does; explain an unfamiliar one in one plain sentence rather than replacing it." | A user reported replies saying "金标" where the recommender-systems field writes "ground truth". Traced to a literal instruction, `translate borrowed terminology into the current project's terms`, added 2026-08-25 and still present in `HEAD` (`4429f3f`). The 2026-08-27 compression (982 → 450 chars) deleted the push but added no counterweight: the correctness-preservation list protects negation, conditions, numbers, units, paths, commands, and error text — every token type that must survive a rewrite except terminology. Adding "terms of art" to that list was the other option and was rejected: a preservation list can say a term must survive but not which form it must survive as, and the correct form depends on field usage, not language. Chinese recommender work writes 召回率 for recall and "ground truth" untranslated, so "keep English" would be wrong in the other direction. +70 chars, body 4309. |
| 2026-09-01 | Treat "guides better work" and "does not impose unnecessary work" as one design invariant, and enforce the second half where the first is enforced: every always-on clause must name a condition that turns it off on trivial work, and the validator's clause-audit prompt now asks that question alongside value and duplication. | Nothing in the plugin measured imposed work. Of 47 recorded decisions ~12 tightened and ~18 loosened, but 11 of the 18 landed in the last two days, so the balance was corrected late rather than maintained. |
| 2026-09-01 | Re-scope the two clauses left with unbounded cost, both introduced the same day: the bug loop applies to a behavior bug, not every bug fix; `Evidence` reads "never generalize from the first match: read the rest of the list or section it came from" instead of "read every source you cite to its end". | Replacing a vague hedge with no condition at all is not the same as replacing it with a checkable one, and the previous round conflated them. "To its end" also licensed reading a 3000-line file to cite one function, while the 2026-08-13 incident it guards was generalizing from the first element of a sampled unit — so the bound belongs on the sampling unit, not the file. |
| 2026-09-01 | Make four clauses checkable instead of self-assessed: drop the bug loop's double hedge ("when feasible and proportionate" → unconditional, with an explicit unsafe/impossible escape); replace `Evidence`'s self-referential "inspect all relevant evidence" with "read every source you cite to its end" plus "run a search across the full scope claimed"; replace `Ownership`'s "likely to help future work" with "outlives this turn and its owner does not already carry"; state in `Ownership` that every file is optional. | Each original relied on the agent grading its own judgment — the exact failure mode already recorded for the compaction rule, where self-assessment is graded leniently under context pressure. A hedge placed before an instruction supplies the excuse to skip it. Optionality was contradictory: `Architecture Checkpoint` said "when present" while the `Ownership` table read as seven required files, and `bootstrap-context` may omit some. |
| 2026-09-01 | Accept the always-on rule at 4204 chars, 4 past the review line, rather than reword for 4 characters. | The line is advisory and asks for a clause audit, which was done: two clauses were tightened with no information lost, from 4243 to 4204. Squeezing the last 4 chars would repeat the recorded failure where budget pressure degraded clarity and produced "covered by another clause" rationalizations. |
| 2026-09-01 | Restore the missing Karpathy goal-driven bug loop: when feasible and proportionate, capture a bug with a minimal reproduction or failing check before fixing it, then rerun the same check; name substitute evidence when reproduction is unsafe or unavailable. | The upstream `multica-ai/andrej-karpathy-skills` rule says `"Fix the bug" → "Write a test that reproduces it, then make it pass"` and its examples explicitly run the same test red then green. This project recorded adopting observable success signals, surgical changes, and verifiable next actions, but omitted the same-evidence-before/after behavior while avoiding rigid Goal/Verify fields. Generic post-change validation does not prove the reported failure existed or that the fix removed it. |
| 2026-09-01 | Replace the overloaded `Safety` section with `Execution` and `Evidence`; keep `Response Style` separate. | `Safety` mixed authorization, defect repair, edit scope, validation, source completeness, epistemic status, and secret handling. Response-style clauses still govern output, including full explanation of security and irreversible actions, so none moved. |
| 2026-06-26 | Keep project memory in `.agent-context/` markdown files, one canonical owner per fact. | Persistent files are the product: project understanding, accumulated experience, and lessons survive chat context loss. Single ownership avoids split writes and missed reads. |

## Lessons Learned
| Date | Type | Lesson | Corrective Guidance |
|------|------|--------|---------------------|
| 2026-09-03 | lesson | A Claude-shaped runtime is not automatically a Codex-shaped product. CodeBuddy's hook envelope matches Codex, but it has a rules slot Codex lacks, so copying the Codex SessionStart path would have shipped a silent double injection on IDE. | When adding a host, split "how the hook talks" from "which component carries the protocol". Use the host's rules slot when it has one; the Codex injection path is the fallback for hosts without one. |
| 2026-09-02 | failure | A user-visible output oddity was diagnosed by reading the rule's current text, which no longer contained the cause. The instruction that produced it, `translate borrowed terminology into the current project's terms`, had been compressed out of the worktree but survives in `HEAD`, so the working copy exonerated a clause the last commit still ships. | When output behavior looks wrong, diff the clause across `HEAD`, the worktree, and the installed copy before concluding, because this repo carries large uncommitted rule edits for days. `git show HEAD:<rule>` answers it in one command. |
| 2026-09-02 | lesson | Deleting a harmful instruction is not the same as preventing the behavior it caused. The 2026-08-27 compression removed "translate borrowed terminology" but left terminology as the only correctness-relevant token type absent from the preservation list, so nothing opposed the behavior once the push was gone. | When a compression round deletes a clause that pushed a behavior, ask whether anything now opposes that behavior. If the answer is no, the deletion needs a counterweight, not just an absence. |
| 2026-09-01 | failure | Editing the protocol's write triggers left five stale restatements: `handoff/SKILL.md` description + body, `update-progress/SKILL.md` (3 lines incl. the `touched files` field retired on 2026-08-27), `COMMANDS.md` behavioral test, and `README.md`. Two survived an earlier sweep of the same class. | When a clause in the protocol changes, grep the old wording repo-wide before claiming the edit is done — skills, `README.md`, and `.agent-context/` all restate it. Prefer pointing at the protocol's `Ownership` table over restating triggers. |
| 2026-09-01 | lesson | A grep-based invariant is worth more than another manual sweep, but its first version flagged the very clause that forbids the retired field, and its scope missed `README.md`. | Assert retired vocabulary per line with an explicit allowance for the prohibition, and include every always-on or user-facing surface in the scan. `scripts/test-hooks.py::test_retired_handoff_field_stays_retired`. |
| 2026-06-26 | failure | Plugin edits do nothing until the local plugin is reinstalled and the host reloads. | Run `./scripts/install-local.sh`, reload Cursor, and read the installed copy before believing a behavior change. |
| 2026-06-26 | lesson | New-chat continuity needs an active handoff, not only project progress. | `PROGRESS.md` carries project state; `HANDOFF.md` carries next action, validation, blockers, and user instructions. |
| 2026-06-26 | lesson | File names shape agent behavior: a narrow name makes agents withhold facts that belong in the file. | Prefer broad names — `MEMORY.md` for decisions, lessons, failures, and corrections alike. |
| 2026-06-26 | lesson | `.agent-context/` files grow forever unless something compacts them. | Summarize old progress and consolidate repeated lessons on every sync. Repeatedly violated since; see the 2026-08-27 entry on why prose alone does not enforce this. |
| 2026-06-26 | lesson | End-of-session handoff reminders must be conditional, fail open, and cap their retries. | Fire only when changed files look newer than `HANDOFF.md`. Refined 2026-08-27 to exclude `.agent-context/` entirely. |
| 2026-06-26 | failure | A new hook script stayed non-executable because `scripts/install-local.sh` hard-coded only the original one. | When adding a hook script, make the install script chmod every script it copies, not a named list. |
| 2026-06-26 | failure | A stop hook that ignores turn status overrides the user's own cancellation. | Emit `followup_message` only for `status: "completed"`; return `{}` for aborted and error turns. Asserted in `scripts/test-hooks.py`. |
| 2026-09-01 | lesson | My char-cost estimate for a five-clause rule edit was off by 2x (+43 predicted, +91 actual) and the validator rejected the result. | Do not quote a budget delta from mental arithmetic on prose.
