# Project Memory

## Decisions
| Date | Decision | Rationale |
|------|----------|-----------|
| 2026-06-27 | Borrow Karpathy-inspired ideas selectively rather than copying the full guideline set. | agent-context should stay focused on durable project memory and lightweight operating protocol. |
| 2026-07-01 | Improve modular-design behavior via an objective signal loop + anti-over-split guard, not more prose or a new heavy skill. | Prose conventions are easily ignored under context pressure and self-assessment is lenient; a measurable stop-hook signal plus a pre-edit checkpoint is lighter and harder to skip. |
| 2026-08-01 | Prefer dual-manifest packaging for Codex (same plugin folder: `.cursor-plugin` + `.codex-plugin`) over a separate fork. | Skills and `.agent-context/` protocol are shared; only rules packaging and hook I/O differ. Avoid maintaining two product trees. |
| 2026-08-03 | Borrow OpenAME's dual-manifest + dual-hooks packaging shape; do not copy their fork-skeleton, multi-plugin marketplace, or giant AGENTS.md workflow. | OpenAME already solved CodeBuddy↔Codex packaging; agent-context only needs the thin packaging layer for one plugin. |
| 2026-08-03 | Eliminate host differences in shared content instead of managing them: no generator, no second copy. | The only real divergence was hardcoded invocation syntax (`/name` vs `$name`). Removing it makes one copy serve both hosts, so OpenAME's generator becomes unnecessary at N=1. |
| 2026-08-03 | Keep the protocol in exactly one file and let every host read that file. | Cursor loads it as a rule, the Codex hook injects it, `AGENTS.md` points at it. Copies had already drifted within days of being made. |
| 2026-08-03 | Stop-hook signals stay advisory on both hosts: Cursor `followup_message`, Codex `systemMessage`. Never Codex `decision: block`. | The staleness signal fires on most working turns, so a forced continuation would roughly double turn count for a state that is harmless mid-session. Hooks inform; the protocol's update triggers instruct. |
| 2026-08-03 | Compute the two stop signals in separate functions even though they share one emission. | They differ by orders of magnitude in firing rate; coupling them meant retuning the noisy one would silently drop the valuable one. |
| 2026-08-03 | Keep the name `agent-context`; differentiate through the description and keywords instead of renaming. | Checked eight candidates (cairn, engram, throughline, warm-start, carryon, binnacle, memory-bank, agentmemory) and every one is taken, most by a direct competitor. A rename relocates you behind a different squatter; it buys no discovery. |
| 2026-08-03 | Trim the always-applied rule by structural deduplication only; leave `Safety`, `Architecture Checkpoint`, and `Hygiene` at full length. | Those three govern behavior, and agents frequently write `.agent-context/` files directly without invoking the matching skill, so the always-on copy is the only thing steering that path. Terser behavioral prose buys tokens at the cost of compliance. |
| 2026-08-03 | Rename the memory directory from `.agent/` to `.agent-context/`, matching the plugin name. | `.agent/` never hard-collided with a harness, but it sat one character from the ecosystem's `.agents/` and this repo root held both at once, which invites misdirected writes by humans and models alike. Owner-namespaced directories cannot collide. Done pre-release at 91 references, when it was cheapest. |
| 2026-08-05 | Import only the epistemic axis from a shared third-party global prompt (mark verified vs assumed, give open questions an owner, state a task's finish condition); reject its long-termism/elegance/communication sections. | The protocol governs where a fact goes and when to write it, never whether the fact is trustworthy — that was the one real gap. The rejected sections produce no memory artifact and no observable output, and adopting them would reverse the 2026-06-27 decision to stay a memory protocol rather than a guideline collection. |
| 2026-08-13 | Extend the epistemic axis from memory writes to asserted conclusions: enumerate the source's contents before concluding, and back a quantified claim with a computed number or mark it an impression. | The 2026-08-05 clause guards `.agent-context/` entries and pre-edit source checks, so a claim that never touches a file was ungoverned — which is where the costly hallucinations happen. Accepted as a narrow exception to the 2026-06-27 "memory protocol, not a guideline collection" boundary because it is checkable, not aspirational. |
| 2026-08-03 | Position on what the project does not have: no index, no database, no daemon, no MCP server, stdlib-only hooks, one source for both hosts. | Competitors ship knowledge graphs (engramx), 29-tool MCP servers (cairn), local Postgres + pgvector (throughline), 93 REST endpoints (agentmemory). Smallness is the only unoccupied axis in this category, and it is what this project actually is. |

## Lessons Learned
| Date | Type | Lesson | Corrective Guidance |
|------|------|--------|---------------------|
| 2026-06-27 | Product guidance | User value is easier to perceive when README names observable success signals. | Prefer "How to know it's working" style signals over only describing internal files. |
| 2026-06-27 | Handoff design | Rigid Goal/Verify fields may become low-signal boilerplate. | Make next actions concrete and verifiable, preferably referencing `.agent-context/COMMANDS.md`, without adding extra template fields. |
| 2026-08-03 | failure | Porting the package to a second host is not the same as porting the product. The first Codex package shipped skills and hooks but no protocol, because Codex has no always-applied rules slot — it silently degraded to "a hook that prints HANDOFF.md". | When adding a host, first ask which component carried the value on the original host, then find that host's equivalent mechanism. Packaging parity proves nothing. |
| 2026-08-03 | lesson | A passing validator can mean the new checks never ran. | Negative-test every new assertion in a throwaway copy: break the thing, confirm the error, restore. |
| 2026-08-03 | lesson | Duplicated content drifts within days, and the drift can look legitimate. | Prefer a single copy plus an automated invariant over two copies plus discipline. Assert the invariant in the validator so it cannot rot. |
| 2026-08-03 | lesson | A signal that fires on almost every turn is usually measuring the wrong moment, not using the wrong threshold. Handoff staleness mid-session is harmless; it only costs anything when context is about to be lost. | Before tuning a threshold, ask when the measured state actually causes harm, and whether the hook fires at that moment. |
| 2026-08-03 | lesson | In a saturated category a distinctive name is not a differentiator, because every good noun is already owned by a competitor. The differentiator is the axis nobody occupies. | Search the category before renaming for distinctiveness. If the name space is exhausted, spend the effort on the one-line positioning and the `keywords` array, which is where marketplace search actually looks. |
| 2026-08-03 | failure | Recorded the leftover `[plugins."agent-context-codex@personal"]` entry in `~/.codex/config.toml` as "harmless, Codex skips unresolvable entries". It was not harmless: because the marketplace now declares `agent-context`, Codex only ever looked for the dead name, the real plugin was never enabled, and the protocol silently never reached any Codex session. Codex had been logging `configured non-curated plugin no longer exists in discovered marketplaces` all along. | A stale enable-entry is not inert; it can be the reason the working thing is never enabled. When a plugin does not appear in the host UI, read the host's own logs before inspecting your own files. Codex logs to `~/.codex/logs_2.sqlite`, table `logs`, column `feedback_log_body`. |
| 2026-08-03 | lesson | Codex has no always-applied rules mechanism, so an `.mdc` file means nothing there; the protocol reaches the model only as `additionalContext` from the plugin's SessionStart hook. "Is the rule in effect?" reduces to "is the plugin enabled, are its hooks trusted, did SessionStart fire?" | Verify Codex behavior at the host level (plugin enabled, hook `statusMessage` visible, logs clean), not by inspecting rule files. |
| 2026-08-03 | failure | Estimated that merging the duplicated `Ownership` and `Update Triggers` sections would cut the always-on rule ~25%; the real result was 9% (790 to 721 tokens). Two sections encoding the same mapping looked half-redundant, but the redundancy sat in the four cheapest bullets (`Commands/checks -> COMMANDS.md` and friends, under 10 tokens each), while the two expensive ones carried real event triggers that had to be kept. | Size the specific lines you intend to delete before promising a percentage. Do not price a refactor off the total size of the sections involved. Also beware rewriting compact slash lists into prose during a merge — the first attempt gave back most of the saving that way. |
| 2026-08-03 | lesson | Only the always-applied rule and the skill `description` lines cost tokens every session; skill bodies are free until invoked. Here that is ~810 always-on against ~1600 on-demand. | When asked to shrink prompts, measure the always-on tier first and leave on-demand content alone; compressing skill bodies optimizes something nobody pays for in the common case. |
| 2026-08-03 | lesson | Generic directory names collide by adjacency, not by exact match. No harness ever claimed `.agent/` (they took `.cursor/`, `.codex/`, `.claude/`), yet it sat one character from `.agents/`, the ecosystem's namespace for skills and plugin marketplaces, and this repo root contained both at once. OpenAME alone references `.agents/` 109 times. | Namespace a directory by its owner, mirroring `.cursor/` and `.github/`, rather than by its genre. Genre names are the ones every tool wants, so they are the ones that collide. |
| 2026-08-03 | failure | Removing the stale config entry was necessary but not sufficient, and the follow-up advice ("enable it in the UI") was wrong: the plugin never appeared in the UI because its status was `not installed`, and that list only renders installed plugins. Copying files to `~/.codex/plugins/` and declaring them in `~/.agents/plugins/marketplace.json` only makes a plugin *discoverable*; `codex plugin add <name>@personal` is what snapshots it into `~/.codex/plugins/cache/<marketplace>/<name>/<version>/` and enables it. Codex runs the cached copy, never the source. | Do not diagnose a host integration through its GUI when the host ships a CLI. `codex plugin list` names the state directly (`not installed` vs `installed, enabled`) and would have ended this in one command. Install scripts must perform the activation step, not print it as a manual instruction. |
| 2026-08-03 | lesson | `codex plugin add` re-copies the source even when the version is unchanged, so it is safe to run unconditionally on every local install. | Re-run it after every plugin edit; bumping the version is not required to refresh the cached snapshot. |
| 2026-08-13 | failure | A rule scoped to the wrong moment reads as coverage but catches nothing. "Verify source before critical edits" would have *passed* the real incident it was meant to prevent: an agent read one field of a payload, ignored two others sitting beside it, and reported "barely used, collapsed to roughly one global program". The source was verified — it was under-sampled, and a qualitative impression was then phrased as a measurement. | Audit a guardrail by replaying a concrete failure against its exact wording, not by matching its topic. Under-sampled evidence and unquantified quantifiers are distinct failure modes from fabrication, and no anti-fabrication rule covers them. |
| 2026-08-03 | failure | Assumed Codex `PreCompact`/`SessionEnd` could drive a handoff write. Neither can: `PreCompact` ignores plain stdout and supports only common output fields, and `SessionEnd` is explicitly advisory. `Stop` is the only Codex event that can steer the agent after a turn. | Check an event's supported output fields before designing around it; "the event exists" does not mean it can influence the agent. |

## Open Questions
| Date | Question | Why it matters / how to settle it |
|------|----------|-----------------------------------|
| 2026-08-05 | Do the two epistemic clauses ("record unverified entries as assumptions"; "quantified claims need a computed number") actually change behavior, or are they inert prose? Assumed effective, not measured. | They contradict the 2026-07-01 finding that prose conventions get ignored under context pressure while objective signals do not. Settle by reading `MEMORY.md` additions and asserted conclusions across the next several projects: if nothing is ever marked assumed or labeled an impression, the axis is decorative and needs a hook-side signal instead. |

# Project Memory

## Decisions
| Date | Decision | Rationale |
|------|----------|-----------|
| 2026-06-26 | Keep project memory in `.agent-context/` files | Persistent files are the plugin's core value: project understanding, accumulated experience, and lessons learned survive chat context loss. |
| 2026-06-26 | Remove cross-review from the plugin | Cross-review diluted the product direction; the plugin should stay small and focus on durable agent context. |
| 2026-06-26 | Expand the plugin from project memory to agent work habits | The user clarified that token savings are secondary; the plugin should make AI-assisted coding smoother, more efficient, more reliable, and easier to resume. |
| 2026-06-26 | Use `.agent-context/MEMORY.md` for long-term project memory | The file stores broader long-term memory, not only technical decisions. |
| 2026-06-26 | Keep always-applied rules minimal | The core rule is injected every session, so detailed templates belong in skills and only routing/recovery/safety guidance should stay always-on. |
| 2026-06-26 | Use single-owner memory routing | Each durable fact should have exactly one canonical `.agent-context/` file to avoid split writes and missed reads. |
| 2026-06-26 | Add a conservative `stop` handoff reminder | A lightweight stop hook can catch stale handoffs without forcing every completion through a heavy workflow. |
| 2026-06-26 | Trim confirmation guardrails to judgment risks | Cursor/tool approvals already cover many mechanical permissions, so the plugin should focus confirmation on ambiguous intent, architecture choices, core behavior, critical config, and destructive operations. |

## Lessons Learned
| Date | Type | Lesson | Corrective Guidance |
|------|------|--------|---------------------|
| 2026-06-26 | lesson | Cross-review is not part of the core product direction | Keep the plugin focused on helping agents understand projects and preserve hard-won context. |
| 2026-06-26 | lesson | New-chat continuity needs an active handoff, not only project progress | Use `PROGRESS.md` for project state and `HANDOFF.md` for next action, touched files, validation, blockers, and user instructions. |
| 2026-06-26 | lesson | File names shape agent behavior | Use broad names like `MEMORY.md` when a file stores decisions, lessons, failures, and corrections. |
| 2026-06-26 | failure | Plugin changes are not active until the local plugin is reinstalled and Cursor reloads | After editing plugin files, run `./scripts/install-local.sh`, reload Cursor, and verify the installed copy if behavior matters. |
| 2026-06-26 | lesson | Long-lived `.agent-context/` files need compaction | Summarize old progress and repeated lessons instead of allowing context files to grow forever. |
| 2026-06-26 | lesson | End-of-session handoff reminders should be conditional | Trigger reminders only when changed files look newer than `HANDOFF.md`, fail open, and cap follow-up loops. |
| 2026-06-26 | failure | Adding a new hook script also requires updating the local install script | Ensure `scripts/install-local.sh` marks all installed hook scripts executable, not only the original session-start script. |
| 2026-06-26 | failure | Stop hooks must respect turn status | Only emit `followup_message` for `status: "completed"`; return `{}` for aborted/error turns so user cancellations are not overridden. |
